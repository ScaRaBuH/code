# Система интеллектуального анализа университетской отчётности

Программный комплекс для автоматизированного анализа статистической и управленческой отчётности образовательных организаций на основе архитектуры **Retrieval-Augmented Generation (RAG)**.

Система позволяет загружать PDF-документы, автоматически извлекать структуру и таблицы, выполнять семантический поиск и получать ответы на вопросы на естественном языке — **полностью локально, без передачи данных во внешние сервисы**.

---

## Возможности

| Функция | Описание |
|---|---|
| 📄 Загрузка документов | Обработка PDF любого объёма |
| 🔍 Семантический поиск | Поиск по смыслу, а не по ключевым словам |
| 📊 Поиск по таблицам | Извлечение числовых показателей |
| 🗂️ Навигация по разделам | Поиск содержимого раздела по номеру |
| 🔀 Анализ нескольких документов | Одновременная работа с несколькими отчётами |
| 🏠 Локальная работа | Без облачных API и внешних серверов |

---

## Архитектура

Система построена по схеме RAG:

```
PDF-документ
    │
    ▼
Docling (парсинг → Markdown)
    │
    ▼
Разбивка на чанки + извлечение таблиц
    │
    ▼
BGE-M3 (эмбеддинги) → FAISS-индекс
    │
    ▼
Запрос пользователя
    │
    ├── Текстовый поиск (FAISS)
    └── Табличный поиск (FAISS)
          │
          ▼
    CrossEncoder (переранжирование)
          │
          ▼
    Qwen3-30B-A3B (генерация ответа)
```

## Стек технологий

**Обработка документов** — Docling, PyMuPDF, Markdown

**Поиск и Retrieval** — FAISS, BGE-M3 Embeddings, BGE-Reranker (CrossEncoder)

**Языковая модель** — Qwen3-30B-A3B, llama-cpp-python, GGUF

**Интерфейс** — Streamlit

**Хранение данных** — SQLite

```

```

## Схема базы данных

**`reports`** — загруженные документы (имя файла, год, дата загрузки)

**`document_chunks`** — текстовые чанки с эмбеддингами и признаком наличия таблиц

**`document_tables`** — извлечённые таблицы с собственными эмбеддингами для табличного поиска

**`sections`** — нумерованные разделы документа для поиска по номеру раздела

## Алгоритм обработки запроса

1. Пользователь задаёт вопрос в чате.
2. Система определяет тип запроса: `SEARCH`, `CALCULATE`, `ANALYZE`, `ANOMALIES`, `STRUCTURE`, `GENERAL`.
3. Выполняется семантический поиск по текстовым чанкам через FAISS.
4. Если запрос содержит количественные показатели — дополнительный поиск по таблицам.
5. Результаты объединяются, дедуплицируются и переранжируются CrossEncoder-моделью.
6. Из топ-результатов формируется контекст (не более 60 000 символов).
7. Контекст и вопрос передаются в языковую модель Qwen3.
8. Из ответа модели удаляются блоки размышлений, возвращается финальный текст.

## Установка

### 1. Клонирование репозитория

```bash
git clone <repository_url>
cd <repository_name>
```

### 2. Виртуальное окружение

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 3. Зависимости

```bash
pip install -r requirements.txt
```

### 4. Языковая модель

Поместите GGUF-файл модели в каталог `models/`:

```
models/
└── Qwen_Qwen3.6-35B-A3B-Q4_K_M.gguf
```

Путь к модели задаётся в `analyzer.py`.
